# 第15天：s16 Workflow Runtime + s17 Goal Loop

今天只解决一个核心问题：

> 当任务不能只靠模型临场决定时，谁规定执行步骤，谁判断整件事可以停止？

建议投入 **120分钟**：s16用75分钟，s17用45分钟。

## 今日定位

### s16 Workflow Runtime

- 所属层：确定性编排与恢复层
- 解决问题：复杂重复流程只靠模型临场规划，不稳定且失败后要重跑
- 接入位置：作为`Workflow`工具挂在Agent Harness下，内部运行保存好的脚本
- 重要程度：高级

### s17 Goal Loop

- 所属层：持续执行与停止控制层
- 解决问题：模型不再调用工具，不等于用户目标已经完成
- 接入位置：主Agent准备停止时的Goal Stop Hook
- 重要程度：高级

今天停止位置：能解释Workflow、普通Agent Loop和Goal Gate的决策权；不实现通用工作流引擎或复杂评测系统。

## 今日可见成果

1. s16 Demo展示阶段、子Agent、进度事件和最终通知
2. Resume时已完成的调用命中Journal缓存
3. s17在目标证据不足时阻止主Agent结束
4. 补充验证结果后，独立判断器允许结束
5. 能说明Workflow结束不代表Goal一定完成

## 时间安排

### 0～10分钟：先画决策权地图

```text
普通Agent Loop：模型决定下一步工具
Workflow：宿主脚本决定固定步骤，模型完成局部任务
Goal Loop：主模型提出结束，独立判断器检查完成条件
```

所有权动作：运行前判断三个组件中“谁决定下一步、谁决定停止”。

### 10～30分钟：阅读s16顶层结构

阅读`s16_workflow_runtime/README.zh.md`，代码只定位：

```python
WorkflowTool
ExecutionState
LocalWorkflowTask
WORKFLOWS
sample_workflow()
```

重点理解：s16不是替换Agent Loop，而是给它增加一个背后执行确定性脚本的工具。

### 30～50分钟：编排与结构化输出

只看：

```python
ExecutionState.agent()
parallel()
pipeline()
phase()
SimpleJsonSchema
```

区分：`parallel`是等齐屏障；`pipeline`让每个Item独立流过多个阶段。结构化输出需要校验，不能直接相信子Agent文本。

### 50～70分钟：Journal与Resume

只看：

```python
WorkflowJournal
workflow_run_lock()
stable key生成
resume_from_run_id
```

重点：脚本会重新执行，但命中稳定Key的`agent()`调用直接复用旧结果。

### 70～85分钟：运行s16 Demo与Resume

```powershell
python s16_workflow_runtime/code.py demo
python s16_workflow_runtime/code.py resume
```

观察事件顺序、输出文件、runId、缓存命中、Agent次数和Token数。

### 85～100分钟：阅读s17停止逻辑

阅读`s17_goal_loop/README.zh.md`，代码只看：

```python
GoalState
PromptGoalEvaluator
GoalController.evaluate_after_turn()
AgentSession
```

重点区分：无工具调用只是“这一轮想停”；Goal判断回答“验收条件是否有证据支持”。

### 100～115分钟：运行Goal实验

在临时目录设置一个可验证目标，例如要求创建文件、读取确认内容。先制造缺少验证证据的情况，再补充证据。

### 115～120分钟：闭卷串联

```text
主Agent选择Workflow
→ Workflow按脚本执行并返回通知
→ 结果进入会话
→ 主Agent准备停止
→ Goal Evaluator检查证据
→ pass或继续
```

## 数据流

### Workflow

```text
主Agent调用Workflow工具
→ Registry找到保存脚本
→ ExecutionState运行agent/parallel/pipeline
→ 进度写入事件流
→ 结果写快照和Journal
→ task_notification返回宿主
```

### Goal

```text
主Agent无function_call
→ Goal Stop Hook
→ 独立Evaluator读取目标和对话证据
→ ok=true则结束
→ ok=false则把原因加入messages并继续
```

## 运行实验

### 正常场景

- s16：执行Demo后使用最近runId恢复
- s17：设置带明确验证方式的Goal并完成

### 失败或边界场景

- s16：子Agent返回不符合Schema的数据，观察校验与重试
- s17：目标只有“弄好它”或缺少工具证据，观察判断器拒绝完成

观察：`task_started`、`task_progress`、`task_notification`、Journal缓存、Goal判断原因和循环状态。

安全要求：使用Demo或临时目录；设置较小的最大轮数；不要让Goal无限自动继续。
