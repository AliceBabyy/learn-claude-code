# 第17天：定制一个本地代码库分析Agent

今天只解决一个核心问题：

> 如何从完整Harness中只选真正需要的能力，组成第一个属于自己的可运行Agent？

建议投入 **120分钟**。代码可以全部交给Codex生成，但需求、取舍、Diff审查和验收由你负责。

## 今日定位

- 所属层：从教学机制到个人项目的第一次落地
- 解决问题：学过很多章节，却没有一个能展示和继续迭代的个人产物
- 接入位置：复用最小Agent Loop，按需求选择工具、权限、计划和上下文能力
- 重要程度：核心实践
- 今日深度：完成CLI版最小产品；不做Web界面、数据库和生产部署

项目目标：输入一个本地代码问题，Agent只能在指定工作目录内搜索、读取和分析，最后输出带文件依据的报告。

## 今日可见成果

1. 新建独立项目目录和README
2. Agent能使用`glob`、`read_file`和`search_text`
3. 所有路径被限制在指定`WORKDIR`
4. Agent在最大轮数内输出带文件路径的结论
5. 越界路径和未知工具会失败，但循环不崩溃
6. 你能解释为什么没有把s10～s17全部复制进来

## 时间安排

### 0～15分钟：定义需求和验收

先写README中的六项：

```text
用户是谁：学习和维护代码的人
输入：一个代码库路径和一个分析问题
输出：结论、证据文件、局限
工具：glob、read_file、search_text
安全边界：只能读取WORKDIR
完成标准：能回答一个真实代码问题并引用证据
```

今天的所有权动作：你先决定保留和删除哪些Harness能力，Codex不得替你扩大范围。

### 15～30分钟：设计最小架构

```text
CLI输入
→ Agent Loop
→ OpenAI Responses API
→ 三个只读工具
→ 路径边界检查
→ function_call_output
→ 最终分析报告
```

第一版只保留：Agent Loop、Tools、Permission、最大轮数、简单日志。

明确不保留：Task System、Background、Cron、Team、MCP、Workflow和Goal Loop。

### 30～60分钟：让Codex生成最小实现

使用下方提示词。生成后先看Diff，不要立即运行。

审查：

- 是否手动保存全部`response.output`
- 是否每个调用都回填相同`call_id`
- 是否使用`Path.resolve()`检查工作目录边界
- 是否只有三个只读工具
- 是否存在最大循环次数

### 60～85分钟：运行正常场景

让Agent分析`learn-claude-code`：

```text
s11如何让后台任务结果重新进入Agent上下文？请给出关键函数和文件依据。
```

观察它是否先搜索、再读取、最后引用真实文件，而不是凭模型记忆回答。

### 85～105分钟：制造失败场景

测试：

- 读取`WORKDIR`之外的文件
- 搜索不存在的文本
- 将最大轮数临时设为2

错误必须进入工具结果，不能让Python进程直接崩溃。

### 105～115分钟：删掉多余内容

检查Codex是否加入缓存、插件系统、Agent类层级、异步框架或配置系统。今天用不到就删除。

### 115～120分钟：闭卷复述

不看代码解释：用户问题如何变成工具调用，工具证据如何回到模型，路径限制在哪一步生效。

## 数据流

```text
用户问题
→ responses.create
→ response.output全部入历史
→ function_call参数解析
→ 权限与路径边界检查
→ 只读工具执行
→ function_call_output按call_id回填
→ 下一轮综合证据
→ 输出结论、文件路径和局限
```

## Codex任务提示词

```text
请在项目根目录新建my-code-agent目录，实现一个最小的本地代码库分析Agent。

要求：
1. 使用OpenAI Responses API和OPENAI_API_KEY、OPENAI_MODEL_ID、
   OPENAI_BASE_URL。
2. 手动维护input历史，每轮保存全部response.output。
3. 只提供glob、read_file、search_text三个只读工具。
4. 所有路径先resolve，并严格限制在启动时指定的WORKDIR内。
5. 使用function_call、json.loads(arguments)和function_call_output；
   结果必须使用原call_id。
6. 未知工具、参数错误、越界路径和执行异常都返回工具结果，不使循环崩溃。
7. 设置最多15轮，达到上限时返回明确中文错误。
8. 最终回答必须包含结论、证据文件和局限。
9. 创建README.md，写明用途、运行方式、配置和验收示例。
10. 所有面向人的注释、提示和错误使用中文。
11. 不复制s15，不加入Task、Memory、MCP、后台任务、多Agent、Workflow、
    Web框架或数据库，不抽取通用Agent类。
12. 修改后运行py_compile，并用离线方式测试路径越界和文本搜索。
```

## 运行实验

### 正常场景

分析s11后台结果注入链路，确认回答引用`code.py`中的真实函数。

### 失败或边界场景

要求读取工作目录外的文件，预期收到明确拒绝；搜索不存在文本，预期返回空结果而不是编造结论。

观察：工具名、参数、路径检查、`call_id`和最终证据。

安全要求：项目只读；不要给`bash`或写文件工具；不要把API密钥写入代码或README。

## 验收标准

- Agent能完成一个真实代码库分析问题
- 最终结论引用至少两个真实文件或代码位置
- 越界读取被拒绝且程序继续运行
- 达到最大轮数能够停止
- 能独立解释完整数据流和功能取舍

今日学习验收问答：

1. 为什么第一版不应该直接复制s15？
2. 只读Agent仍然需要哪些权限边界？
3. 如何判断回答来自工具证据而不是模型猜测？
4. 下一项功能应该由什么真实需求决定？
