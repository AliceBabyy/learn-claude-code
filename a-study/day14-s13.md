# 第14天：s13 Agent Teams

今天只解决一个核心问题：

> 多个长期存活的Agent如何分工、通信并协调共享任务，而不把彼此上下文混在一起？

建议投入 **120分钟**。

## 今日定位

- 所属层：Harness多Agent协调层
- 解决问题：一次性Subagent无法持续认领任务、相互通信和等待审批
- 接入位置：Lead Agent通过团队工具管理Teammate；每个成员拥有独立Agent Loop和历史
- 重要程度：高级能力，理解架构边界比掌握全部实现更重要
- 今日深度：理解身份、任务、消息、协议、工作目录隔离；不深挖线程锁和Git Worktree实现

## 今日可见成果

1. Lead创建任务并启动一个Teammate
2. Teammate拥有独立`messages`，可以认领并完成任务
3. Lead与Teammate通过`MessageBus`交换消息
4. Plan审批或Shutdown请求能够按`request_id`匹配响应
5. 能说清Agent Team和s06 Subagent的区别

## 数据流

```text
Lead调用spawn_teammate
→ TeammateRuntime创建独立messages和线程
→ 成员从共享TaskStore认领任务
→ 在自己的工作目录调用模型和工具
→ 工具结果写回成员自己的历史
→ MessageBus发送状态或结果
→ Lead收件箱注入团队事件
→ Lead继续协调
```

## 运行实验

### 正常场景

```text
创建一个“阅读s13 README并总结Team与Subagent差异”的任务，
启动名为reader的成员认领并完成，然后让它把结果发回Lead。
```

观察任务状态、成员身份、独立调用历史和Lead收件箱。

### 失败或边界场景

- 启动重名成员
- 给不存在的成员发消息
- 使用错误`request_id`回复Plan请求

预期：返回明确错误，主Agent和其他成员不崩溃。

安全要求：只做读取任务；不要让成员修改真实代码；不创建或删除真实Worktree。
