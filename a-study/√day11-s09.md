# 第11天：s09 Memory

今天只解决一个核心问题：

> 哪些信息值得跨会话保存，以及新任务开始时如何只召回相关记忆，而不是把全部历史重新塞给模型？

建议投入 **90分钟**。

今天重点是记忆的完整生命周期：

```text
候选信息
→ 持久性判断
→ 独立文件存储
→ 索引重建
→ 根据新请求选择
→ 按需加载正文
→ 重复与过期记忆整理
```

## 今日定位

- 所属层：Harness持久记忆层
- 解决问题：新会话没有旧`messages`，但用户偏好和项目事实仍可能有用
- 接入位置：模型调用前召回，当前回合结束后提取和写入
- 重要程度：核心
- 今日深度：真正验证存储、索引、筛选和跨会话召回；模型自动提取和整理只追踪主流程

## 与s08的边界

```text
s08 Context Compact
→ 当前会话太长
→ 决定哪些细节可以从上下文移走

s09 Memory
→ 会话结束后仍需复用
→ 决定哪些稳定信息值得长期留下
```

Transcript也不是Memory：

```text
Transcript：完整归档，适合追溯
Memory：选择性知识，适合新任务直接复用
```

## 今日可见成果

今天结束时必须看到：

1. 一条用户偏好被保存为独立Markdown文件
2. `MEMORY.md`索引自动更新
3. 模拟新会话时能够召回相关偏好
4. 不相关记忆不会被加载
5. 当前任务临时要求被拒绝持久化
6. 重复记忆不会重复写入

## 本地实现结构

本地`s09_memory/code.py`实现四个子系统：

| 子系统 | 关键函数 | 作用 |
|---|---|---|
| 存储 | `write_memory_file`、`rebuild_memory_index` | 一条记忆一个文件，并维护目录索引 |
| 召回 | `select_relevant_memories`、`load_memories` | 先选目录，再读取正文 |
| 提取 | `extract_memories`、`should_store_memory` | 从当前对话筛选可持久信息 |
| 整理 | `consolidate_memories` | 合并重复、修正冲突、淘汰过时信息 |

当前代码仍使用Anthropic。今天继续采用离线实验，避免API迁移掩盖Memory的数据模型和生命周期。

## 10～25分钟：理解存储结构

只追踪：

```python

MEMORY_INDEX
MEMORY_TYPES

```

单条记忆格式：

```markdown
---
name: user-preference-tabs
description: 用户偏好使用Tab缩进
type: user
---

用户编写代码时偏好Tab缩进，而不是空格。
```

为什么分成索引和正文：

```text
MEMORY.md
→ 内容短，供选择器查看“有哪些记忆”

单条Markdown正文
→ 只有被选中时才加载
```

这与`s07 Skill Loading`的渐进披露结构类似：先看目录，再加载正文。

## 25～35分钟：理解写入闸门

重点阅读：

```python
should_store_memory()
TEMPORARY_MEMORY_MARKERS
validate_memory_record()
```

候选记忆必须同时满足：

```text
scope == persistent
type属于允许类型
name、description、body完整
不包含临时语义
没有与已有记忆重复
```

注意职责边界：

```text
模型：提出候选记忆
Harness：校验并决定是否真正写盘
```

不能让模型输出什么就永久保存什么。

## 数据流

### 写入

```text
当前对话结束
→ 模型提取候选记忆
→ Harness校验持久性、类型、完整性、重复性
→ 写入独立Markdown
→ 重建MEMORY.md索引
```

### 召回

```text
新用户请求
→ 查看记忆目录
→ 选择最多5条相关记忆
→ 加载正文并限制总长度
→ 注入System背景
→ 当前用户请求优先于旧记忆
```

## 验收标准

- 实际生成三条独立记忆文件和一个索引
- 使用全新messages成功召回缩进偏好
- 不相关记忆没有进入召回正文
- 临时任务候选被拒绝
- 重复候选被拒绝
- 能区分Context、Transcript和Memory
- 实验没有发起真实API请求
