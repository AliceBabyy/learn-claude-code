# 第12天：s14 MCP Tools

今天只解决一个核心问题：

> Harness如何发现外部工具，并把它们安全地接入原有Agent Loop？

建议投入 **90分钟**。

## 今日定位

- 所属层：Harness外部工具接入层
- 解决问题：每接一个外部服务都手写工具定义和调用逻辑
- 接入位置：模型调用前动态组装工具池，执行时经宿主权限检查后分发
- 重要程度：重要增强，也是求职中常见的Agent扩展方式
- 今日深度：掌握连接、发现、命名、组装、权限、调用、回填；不研究真实Transport和完整MCP协议

当前代码已经使用OpenAI Responses API。本章的`docs`和`deploy`是进程内模拟Server，用来展示MCP边界，不是真实网络通信。

## 今日可见成果

1. 连接前工具池只有基础工具和`connect_mcp`
2. 连接`docs`后出现`mcp__docs__search`和`mcp__docs__get_version`
3. 动态工具结果通过`function_call_output`回填
4. 连接不存在的Server会失败，但Agent Loop不崩溃
5. `deploy.status`可放行，`deploy.trigger`仍由宿主权限策略控制

## 数据流

```text
第1轮组装基础工具
→ 模型调用connect_mcp(name="docs")
→ Harness创建MCPClient并保存工具定义
→ 连接结果回填
→ 第2轮重新组装工具池
→ 模型调用mcp__docs__search
→ 宿主权限检查
→ Server handler执行原始search
→ 结果按原call_id回填
```
