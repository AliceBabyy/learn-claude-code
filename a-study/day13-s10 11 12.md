# 第13天：s10～s12 持久任务、后台任务与定时任务

今天只解决一个核心问题：

> Harness如何让工作跨步骤、跨等待时间甚至跨会话继续存在？

建议投入 **120分钟**。这是快速定位日：s10用50分钟，s11用40分钟，s12用30分钟。

## 今日定位

| 章节 | 所属层 | 解决问题 | 接入位置 | 重要程度 |
|---|---|---|---|---|
| s10 Task System | 持久任务状态层 | Todo无法表达依赖、认领和跨会话恢复 | 作为任务工具接入Loop | 重要增强 |
| s11 Background Tasks | 异步执行层 | 慢命令阻塞主循环 | 工具执行与下一轮输入之间 | 重要增强 |
| s12 Cron Scheduler | 时间调度层 | 工作无法在未来自动开始 | Agent Loop外部事件入口 | 高级 |

今天停止位置：能区分三者保存的状态、触发时机和结果进入会话的路径；不研究线程、进程组、文件锁和完整Cron实现。

## 今日可见成果

1. s10创建三个带依赖的任务，阻塞任务不能提前认领
2. 完成前置任务后，下游任务被解锁
3. s11后台命令立即返回`bg_id`，随后结果以通知进入会话
4. s12创建一个调度任务，并看到到期Prompt进入Agent Loop

## 数据流

### s10

```text
模型调用任务工具 → TaskStore写JSON → 依赖检查 → 状态迁移 → 解锁下游
```

### s11

```text
function_call → 后台线程启动 → 立即回填bg_id
→ 后台完成 → task_notification注入下一轮
```

### s12

```text
schedule_cron → 保存CronJob → 调度线程匹配时间 → 入队
→ Agent空闲 → Scheduled Prompt进入Agent Loop
```

## 运行实验

### 正常场景

- s10：按依赖顺序认领和完成任务
- s11：后台执行短命令，同时执行一个同步工具
- s12：创建一次性调度并等待触发

### 失败或边界场景

- s10：前置任务未完成时认领下游
- s11：后台命令以非零退出码结束
- s12：提交非法Cron表达式

观察：JSON状态、`bg_id`、`task_notification`、调度队列和中文错误信息。

安全要求：使用临时练习目录；后台命令只做短暂sleep和打印；定时任务不修改文件。
